# Metal AM trustworthy AI benchmark

Code and records for the survey and the controlled benchmark in "Trustworthy Artificial Intelligence in Metal Additive Manufacturing through a Critical Survey and a Controlled Benchmark" (Ali Al Bataineh and Bandi Vamsi).

The benchmark classifies full-frame laser powder bed fusion images as Good or Defect in two modalities, optical tomography (OT) and powder bed (PB) imaging. Four ImageNet-pretrained convolutional networks (ResNet18, ResNet50, EfficientNet-B0, MobileNetV3-Large) are trained with three seeds under two split protocols:

* Protocol R (mixed-build split): one stratified 70/15/15 train/validation/test split per modality.
* Protocol S (leave-one-build-out): each of the three builds B1, B2 and B3 is held out in turn as the test set; the other two builds are split 85/15 into train and validation.

This gives 8 tasks, 32 groups (architecture x task) and 96 training runs. Beyond predictive performance, the code evaluates calibration (validation-fitted temperature scaling), three-seed ensemble uncertainty, robustness to five generic image corruptions at three severities, paired block-resampling statistics for architecture contrasts, frozen-embedding reference baselines, Grad-CAM descriptors against the annotated bounding boxes, and inference efficiency.

The repository contains:

* `src/amtrust/`: the reusable implementation (data cohort, splits, preprocessing, models, training, metrics, calibration, uncertainty, robustness, statistics, baselines, Grad-CAM, efficiency, tables and figures).
* `scripts/`: command-line entry points for every stage and for reproduction.
* `configs/benchmark.json`: every scientific parameter and seed.
* `results/`: the reported results as CSV files (see `results/README.md`).
* `tests/`: unit tests on synthetic data (standard library `unittest`).
* `survey/`: the search, screening, sampling and evidence-coding scripts and records of the survey (see `survey/README.md`).
* `figures/`: the six figures of the article as vector PDF files. Figure 1 is drawn by `python scripts\make_framework_figure.py outputs\figures`. Figures 2 to 6 are written by `python scripts\reproduce.py --fast` as `fig_macro_f1_heatmap` (Figure 2), `fig_calibration_change` (Figure 3), `fig_uncertainty_auroc` (Figure 4), `fig_robustness_direction` (Figure 5) and `fig_efficiency` (Figure 6).

Trained weights files, per-sample predictions and per-image split lists are not distributed; the per-group results in `results/` are the values reported in the article, and `scripts/make_splits.py` regenerates the per-image partitions from the public dataset with the seed and the expected per-task counts in `configs/benchmark.json`. The fast reproduction path regenerates every reported table and data figure from `results/*.csv`; the table snippets contain the reported values, which the typeset tables of the article present in a different layout and precision. The full path retrains everything from the public dataset.

## Dataset

The images are the public dataset "Annotated Image Dataset for defects detection in Laser Powder Bed Fusion" by Xinyi Yin, Jan Sher Akmal, Mika Salmi and Roy Björkstrand, Zenodo, DOI [10.5281/zenodo.14996806](https://doi.org/10.5281/zenodo.14996806), licensed CC BY 4.0. The data are not redistributed here. Download these two files from the Zenodo record into one folder (the data root):

| File | MD5 |
|---|---|
| `Original Images and Manual Labels.zip` | `9d5ed884aecacb9ada5d0cca7c15d4b7` |
| `Croped Defects and Classification.zip` | `22a0bb286349584c61bab5ff47f3ea73` |

The third file of the record (`Preprocessed Data.zip`) is not used. `scripts/prepare_data.py` checks both MD5 checksums.

Cohort construction (`src/amtrust/data.py`):

* Model inputs are the full frames of `Original Images and Manual Labels.zip` (OT: 2000 x 2000 RGB; PB: 1280 x 1024 greyscale).
* The Good/Defect label of each full frame is the folder (`Good` or `Defects`) of the image with the same modality and filename stem in `Croped Defects and Classification.zip`. Defect is the positive class.
* The build token is the first underscore-delimited part of the filename (for example `SI383820211201123521`); the sequence index is the second part. Build labels: B1 = `SI383820211201123521`, B2 = `SI383820240226095904`, B3 = `SI383820240318120348`.
* One group of five byte-identical OT Good frames exists in build B3; the four copies other than the lowest sequence index are excluded, giving 5,308 images in the primary cohort (OT 2,670, PB 2,638).
* Annotation anomalies (two Defect frames with empty XML files and one with a zero-width box) remain in the primary cohort. They have no valid reference box and are therefore not eligible for the Grad-CAM cohort, and they are excluded from the strict sensitivity cohort (5,305 images).
* Reference boxes for Grad-CAM come from the Pascal-VOC XML files (`OT_label`, `PB_label`). The OT boxes are labelled "overheated" in the source annotations and the PB boxes "defects".

## Fast reproduction (tables and figures from the shipped results)

Windows PowerShell, from the repository folder:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-fast.txt
python scripts\reproduce.py --fast
python -m unittest discover -s tests
```

`reproduce.py --fast` reads `results\*.csv` and writes LaTeX table snippets and matching CSV tables to `outputs\tables\` and the figures (vector PDF and 600 dpi PNG) to `outputs\figures\`. It runs on the CPU in less than 20 seconds.

## Full reproduction (from the Zenodo archives)

The full path needs an NVIDIA GPU with CUDA. Its total runtime has not been measured on current hardware and is expected to be long (96 training runs of up to 30 epochs each, followed by corrupted-input inference for 1,440 run-condition pairs and Grad-CAM for 2,880 run-sample pairs).

```powershell
py -3.10 -m venv .venv-full
.\.venv-full\Scripts\Activate.ps1
python -m pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu121
python -m pip install -r requirements.txt
$env:AMTRUST_DATA_ROOT = "$HOME\amtrust\data"       # folder holding the two zip files
$env:AMTRUST_OUTPUT_ROOT = "$HOME\amtrust\outputs"
python scripts\reproduce.py --full
```

The data root and output root can also be given as `--data-root` and `--output-root` on every script; the defaults are `data\` and `outputs\` inside the repository. On Windows keep the output root path short, because run folder names are long and some tools do not accept paths longer than 260 characters. ImageNet weights are downloaded by torchvision into `<data root>\pretrained\` on first use and verified by SHA-256; `--weights-dir` points to an existing folder of the four torchvision weights files instead.

Individual stages can be run separately, in this order:

```powershell
python scripts\prepare_data.py      # MD5 check, extraction, manifest, reference boxes
python scripts\make_splits.py       # split files and results\split_counts.csv in the output root
python scripts\train.py --index 1   # one run (1 to 96); run_all.py runs all of them
python scripts\run_all.py --steps predictive,calibrate,uncertainty,robustness,stats,baselines,xai,efficiency,tables,figures
```

The full path writes its results CSV files to `<output root>\results\` (the shipped `results\` folder is not overwritten) and builds tables and figures from there. `make_tables.py` and `make_figures.py` accept `--results-dir` to point at either folder.

A CPU smoke test of the training loop (functional check only; not comparable with the reported numbers):

```powershell
python scripts\train.py --index 1 --allow-cpu --max-epochs 1 --limit-train 16 --limit-val 8 --limit-test 8
```

## Seeds and protocol constants

* Split seed: 20260916 (`train_test_split(random_state=20260916, shuffle=True)`, stratified by build x class).
* Training seeds: 20260916, 20260917, 20260918 (Python, NumPy, torch CPU and CUDA, and the training data loader generator).
* Random-forest baseline seeds: 20260916, 20260917, 20260918.
* Corruption noise seeds: first 8 hexadecimal digits of SHA-256(`ROBUSTNESS_V1|gaussian_intensity_noise|S<k>|<sample id>`).
* Resampling seeds: base 20260916; first 16 hexadecimal digits of SHA-256(`STATISTICAL_AMENDMENT_V1_1|BASE=20260916|PHASE=<BOOTSTRAP or RANDOMIZATION>|TASK=<protocol>|<modality>|<fold id>|L=<L>`) modulo 2^32.
* Grad-CAM cohort: SHA-256(`METAL_AM_XAI_36A_CANDIDATE_V1|<protocol>|<modality>|<fold id>|<sample id>`).

Training: 512 x 512 input, no augmentation, full fine-tuning, unweighted cross-entropy, AdamW (learning rate 1e-4, weight decay 1e-4), no scheduler, batch size 8, float16 autocast with gradient scaling on CUDA, at most 30 epochs, early stopping on validation NLL with patience 6 and minimum improvement 1e-4, restoration of the lowest-validation-NLL weights, Defect predicted when P(Defect) >= 0.5. Deterministic settings: `torch.use_deterministic_algorithms(True)`, cuDNN deterministic, cuDNN benchmark off, `CUBLAS_WORKSPACE_CONFIG=:4096:8`, `num_workers=0`, a fresh process per run. All further constants are in `configs/benchmark.json`.

## Definitions used in the reported results

* AUPRC is a step average precision: test samples are sorted by decreasing P(Defect) with a stable mergesort and the precision at the rank of each positive is averaged, without grouping tied scores. It can differ from `sklearn.metrics.average_precision_score` when probabilities are tied.
* The NLL in the predictive tables is computed on the stored softmax probabilities clipped to [1e-12, 1] without renormalisation, which limits each sample to -ln(1e-12) = 27.63 nats. The calibration NLL is a log-sum-exp cross-entropy on logits without clipping. The two agree except where probabilities saturate (EfficientNet-B0, Protocol S, OT, held-out B3).
* Brier score and ECE are binary, on P(Defect) against the Defect indicator; ECE uses 10 equal-width bins with the last bin closed.
* Temperature scaling: T = exp(eta), eta fitted on validation logits by bounded scalar minimisation over [ln 0.01, ln 100]. A run whose solution lies within 1e-7 of a bound is reported as not estimable and contributes no calibrated values; no value is imputed.
* Uncertainty uses the three seeds as an equal-weight ensemble of uncalibrated probabilities. The entropy gap (predictive entropy minus expected member entropy) is the generalised Jensen-Shannon divergence of the members and is not interpreted as Bayesian mutual information.
* Group summaries are means and sample standard deviations (ddof = 1) over the three seeds unless stated otherwise.

## Configuration facts and known deviations

These facts describe how the reported results were produced. They are encoded in `configs/benchmark.json` so that they can be reproduced or switched off.

1. Grad-CAM layers. The reported Grad-CAM results use the layers in `xai.layers`: ResNet18 and ResNet50 `layer3` (primary) and `layer4` (complementary); EfficientNet-B0 `features.6` and `features.8`; MobileNetV3-Large `features.12` and `features.16`. Two early runs used different settings: EfficientNet-B0, Protocol R, OT, seed 20260916 used `features.3` as the primary layer, and ResNet18, Protocol R, OT, seed 20260916 used `layer2.1` (primary) and `layer4.1` (complementary) with maps stored without per-map min-max normalisation. These settings are listed under `xai.run_layer_overrides` and are applied by default (`xai.apply_run_layer_overrides` is `true`), so the full path reproduces the reported Grad-CAM results; set it to `false` to compute every run at the standard layers with normalised maps.
2. Excluded thresholded run. Because the maps of ResNet18, Protocol R, OT, seed 20260916 were not normalised, no pixel reaches the 0.50 overlap threshold. This run is excluded from the threshold-based overlap metrics (IoU, Dice, precision, recall), which therefore use 95 runs (2,850 run-sample pairs); the threshold-free metrics use all 96 runs (2,880 pairs). The rule is `xai.threshold_metric_excluded_runs` with `xai.apply_threshold_metric_exclusion`.
3. Reference-box projection. Native box coordinates are scaled by the resized extent of each axis (new width / width, new height / height) and shifted by the padding offsets (`xai.box_projection = "resized_extent"`). For PB the vertical factor is 410/1024 rather than 512/1280; `"long_side"` selects the uniform factor 512 / max(width, height).
4. Decision rule in the uncertainty analysis. Member votes and the ensemble prediction use P(Defect) > 0.5 (an exact 0.5 counts as Good), whereas training, evaluation and robustness use P(Defect) >= 0.5. No stored member test probability equals 0.5 exactly.
5. Validation logits for temperature scaling were produced from the saved model states after training (batch size 8, FP32), not during training.
6. One calibration fit reached the lower temperature bound (MobileNetV3-Large, Protocol S, OT, held-out B3, seed 20260918); its group reports calibrated values over two seeds.
7. Corruptions are applied to the whole 512 x 512 canvas, including the PB padding band.
8. Run numbering. The training manifest orders runs by architecture (ResNet18, ResNet50, EfficientNet-B0, MobileNetV3-Large), then task, then seed (runs 1 to 96). Efficiency measurements use the lowest-numbered run of each architecture (Protocol R, OT, seed 20260916).
9. Statistics. Block length 16 is the primary analysis and block lengths 8 and 32 are sensitivity analyses. Block length 32 is not used for the two Protocol R tasks because build B2 has fewer than 64 test images in each of them.
10. Efficiency timing is defined for CUDA only. `scripts/efficiency.py --device cpu` runs an FP32 CPU timing that writes `efficiency_cpu_not_comparable.csv` and is not comparable with the reported values.

## Results files and column definitions

Group identifiers: `architecture` is one of `resnet18`, `resnet50`, `efficientnet_b0`, `mobilenet_v3_large`; `protocol` is `R` or `S`; `modality` is `OT` or `PB`; `fold_id` (`fold` in `predictive_groups.csv`) is `R_MAIN` for Protocol R and `S<k>_HOLDOUT_<build token>` for Protocol S, where S1, S2 and S3 hold out builds B1, B2 and B3. `group_id` joins architecture, protocol, modality and fold id with `__`. Unless stated otherwise `_mean` and `_sd` are the mean and sample standard deviation (ddof = 1) over seeds. Columns ending in `_derived` are recomputed from other columns of the same file, except `nll_delta_mean_derived`, `brier_delta_mean_derived` and `ece_delta_mean_derived` in `calibration_groups.csv`, which are paired means over the per-seed values of the calibrated seeds.

| contrast, model_a, model_b | `capacity_contrast` (ResNet50 minus ResNet18), `efficient_vs_high_capacity` (EfficientNet-B0 minus ResNet50), `deployment_vs_high_capacity` (MobileNetV3-Large minus ResNet50) |
| estimate | Mean over the three seeds of the metric difference, model A minus model B |
| ci95_low, ci95_high | 2.5 and 97.5 percentiles of 5,000 paired build-stratified moving-block bootstrap replicates |
| raw_p | Two-sided block randomisation p-value, (E + 1) / (10000 + 1) |
| holm_p | Holm-adjusted p-value across the three contrasts of the task, metric and block length |
| holm_significant_005_derived | TRUE when holm_p < 0.05 |
| ci_excludes_zero_derived | TRUE when the interval excludes zero |
| analysis | `primary` (block length 16) or `sensitivity` |

## Tests

`python -m unittest discover -s tests` runs unit tests on synthetic data: metric definitions (step AP against scikit-learn with and without ties, clipped NLL, logit NLL, ECE), temperature fitting and the boundary rule, entropy-gap identities, corruption determinism and seeding, block-resampling helpers, box projection and pixel-centre masks, localisation metrics, Grad-CAM map shapes on a randomly initialised ResNet18 and the existence of every configured Grad-CAM layer, split stratification on a synthetic cohort, and table generation.
